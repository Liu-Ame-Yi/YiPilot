## 2. Hmzbo：backend 拥有 create/kill，多个工具调用复用一个实例

- **生命周期：** `OpenSandboxBackend.create()` 调用异步 `Sandbox.create()`，返回绑定同一 sandbox 的 backend；`execute/upload_files/download_files` 都使用该对象。示例把 backend 交给 DeepAgent，agent.invoke 后 finally 调 `backend.kill()`。粒度由应用放置 create 的位置决定，源码没有自动按 session/task 分配 ID 的 manager。[backend.py](https://github.com/Hmzbo/deepagents-opensandbox-backend/blob/0cb7471d7d25099687f9f9c37cb3303a40b56380/src/deepagents_opensandbox_backend/backend.py)
- **复用：** 默认 create timeout 为 30 分钟，image/entrypoint 固定到当时 code-interpreter 布局。execute 收 shell 字符串；传入 timeout 时才构造服务端 RunCommandOpts，未设独立客户端墙钟 deadline，也没有每条命令新建容器。[backend.py](https://github.com/Hmzbo/deepagents-opensandbox-backend/blob/0cb7471d7d25099687f9f9c37cb3303a40b56380/src/deepagents_opensandbox_backend/backend.py)
- **同步/异步桥接：** 全进程共享一个后台 event loop/thread，所有 SDK await 通过 run_coroutine_threadsafe 提交；同步方法等待 future.result。aexecute 等由 BaseSandbox 的线程卸载默认实现提供。源码说明之前每操作 asyncio.run/跨 loop 客户端与手工异步桥接出现问题；这是该集成的经验，不表示必须给所有应用引入全局线程。[后台 loop](https://github.com/Hmzbo/deepagents-opensandbox-backend/blob/0cb7471d7d25099687f9f9c37cb3303a40b56380/src/deepagents_opensandbox_backend/_loop.py)、[backend.py](https://github.com/Hmzbo/deepagents-opensandbox-backend/blob/0cb7471d7d25099687f9f9c37cb3303a40b56380/src/deepagents_opensandbox_backend/backend.py)
- **文件：** 上传使用 WriteEntry(bytes) 和 files.write_files，下载用 files.read_bytes；只检查绝对路径，以文件级 response 返回失败，下载错误再 get_file_info 分类。不是自动同步宿主目录；上层负责选择路径、上传输入、下载产物。[文件实现](https://github.com/Hmzbo/deepagents-opensandbox-backend/blob/0cb7471d7d25099687f9f9c37cb3303a40b56380/src/deepagents_opensandbox_backend/backend.py)
- **清理边界：** `kill()` 只调用 SDK sandbox.kill，没有 local close/destroy；atexit 只停止共享 loop，不销毁全部远端 sandbox。源码没有本地结果稳定导出、orphan 对账、清理 attestation、日志字节上限或任务目录审核。stdout/stderr 全量累计后用换行拼接为展示输出，不能复制成 YiPilot 的原始字节证据合同。[生命周期/输出](https://github.com/Hmzbo/deepagents-opensandbox-backend/blob/0cb7471d7d25099687f9f9c37cb3303a40b56380/src/deepagents_opensandbox_backend/backend.py)、[loop stop](https://github.com/Hmzbo/deepagents-opensandbox-backend/blob/0cb7471d7d25099687f9f9c37cb3303a40b56380/src/deepagents_opensandbox_backend/_loop.py)
- **依赖时间边界：** pyproject 为包 0.1.0、Python ≥3.12、deepagents ≥0.2.0、opensandbox ≥0.1.13，没有固定 SDK 上限；“async-only SDK”等注释及部分旧 server 默认安全说明属于当时版本语境，不能当作 1.1.1 的现行 API/默认配置结论。[pyproject](https://github.com/Hmzbo/deepagents-opensandbox-backend/blob/0cb7471d7d25099687f9f9c37cb3303a40b56380/pyproject.toml)

**测试证据：** fixture 为 class scope，整个 SandboxIntegrationTests 类共享 backend，并在 finally kill；普通 push/PR 仅 lint、build/import smoke，真实 Docker integration 需手动 workflow_dispatch 且 run_integration=true。2026-07-15 的指定手动运行中，拉 code-interpreter 镜像、启动 opensandbox-server、执行 pytest 的 integration job 均成功；server/SDK 使用非严格固定依赖，因此这不是 1.1.1 兼容性证明。[fixture](https://github.com/Hmzbo/deepagents-opensandbox-backend/blob/0cb7471d7d25099687f9f9c37cb3303a40b56380/tests/integration_tests/test_sandbox.py)、[workflow](https://github.com/Hmzbo/deepagents-opensandbox-backend/blob/0cb7471d7d25099687f9f9c37cb3303a40b56380/.github/workflows/ci.yml)、[实际成功 job](https://github.com/Hmzbo/deepagents-opensandbox-backend/actions/runs/29426739966/job/87391111736)

## 3. Ayush：adapter 只管工具原语，调用者拥有 create/destroy

- **生命周期：** 构造器只接收已存在的 `SandboxSync`，不创建、重连、续期或删除。README 和测试由应用先 SandboxSync.create，再注入 OpenSandboxBackend，最后 sandbox.destroy；adapter 与生命周期分离的边界非常明确。[adapter](https://github.com/AyushSonuu/langchain-sandbox-opensandbox/blob/c0ac09f57397f2dbe80b0c40ad5ee37799f90d57/langchain_opensandbox/sandbox.py)、[fixture](https://github.com/AyushSonuu/langchain-sandbox-opensandbox/blob/c0ac09f57397f2dbe80b0c40ad5ee37799f90d57/tests/integration_tests/test_sandbox.py)
- **复用与执行：** execute、upload、download 使用同一个传入 handle；BaseSandbox 基于 execute 提供 ls/read/write/glob/grep 等高层工具。execute 接 shell 字符串，默认单 command timeout=1800 秒，可覆盖，0 表示无服务端 timeout；并不定义 conversation/session/task 的生命周期。[adapter](https://github.com/AyushSonuu/langchain-sandbox-opensandbox/blob/c0ac09f57397f2dbe80b0c40ad5ee37799f90d57/langchain_opensandbox/sandbox.py)
- **文件：** write_files(bytes) / read_bytes；逐文件 response。上传先 shell test -e，再批量写入，试图拒绝覆盖；这不是原子“不存在才创建”，并发写入时仍需额外保证。下载失败再 shell probe 分类 missing/directory/permission，而非可信宿主扫描。[adapter](https://github.com/AyushSonuu/langchain-sandbox-opensandbox/blob/c0ac09f57397f2dbe80b0c40ad5ee37799f90d57/langchain_opensandbox/sandbox.py)
- **异常/证据边界：** 命令异常上抛，文件写/读异常转换为文件 response；未见自动 interrupt/destroy 或 lost-create 恢复。输出按文本日志重组，stderr 加标签，固定 truncated=False，没有内建日志流预算；不提供原始字节保真、稳定导出或清理证明。[adapter](https://github.com/AyushSonuu/langchain-sandbox-opensandbox/blob/c0ac09f57397f2dbe80b0c40ad5ee37799f90d57/langchain_opensandbox/sandbox.py)
- **版本：** 当前包 0.1.2，Python ≥3.11，deepagents ≥0.7.0,<0.8.0，opensandbox ≥0.1.15。其声明输出“逐行且已剥离换行”的注释不应替代目标 OpenSandbox 版本的真实 SSE 合同。[pyproject](https://github.com/AyushSonuu/langchain-sandbox-opensandbox/blob/c0ac09f57397f2dbe80b0c40ad5ee37799f90d57/pyproject.toml)、[输出实现](https://github.com/AyushSonuu/langchain-sandbox-opensandbox/blob/c0ac09f57397f2dbe80b0c40ad5ee37799f90d57/langchain_opensandbox/sandbox.py)

**测试证据：** live fixture 也是 class scope，环境无 OPENSANDBOX_DOMAIN 时整模块 skip；finally 调 destroy。README 和最新发布 commit 声明 live conformance 86/86，无 mock/no skip；但核查的常规 CI 只有 lint/unit，最新成功 run 的 Python 3.11/3.12/3.13 job 不含启动 server/live pytest 步骤。因此“86/86”列为作者报告的实测结果，不能用常规 CI 绿灯替代核验。[fixture](https://github.com/AyushSonuu/langchain-sandbox-opensandbox/blob/c0ac09f57397f2dbe80b0c40ad5ee37799f90d57/tests/integration_tests/test_sandbox.py)、[workflow](https://github.com/AyushSonuu/langchain-sandbox-opensandbox/blob/c0ac09f57397f2dbe80b0c40ad5ee37799f90d57/.github/workflows/ci.yml)、[作者 release commit](https://github.com/AyushSonuu/langchain-sandbox-opensandbox/commit/c0ac09f57397f2dbe80b0c40ad5ee37799f90d57)、[CI run](https://github.com/AyushSonuu/langchain-sandbox-opensandbox/actions/runs/31995943789)

## 4. AgentScope 主仓库：持久 workspace，而非一次性执行任务

### 4.1 所有权与复用粒度

- **三层职责：** Backend 仅适配 exec_shell/read_file/write_file；Workspace 负责找已有 sandbox、create/connect/resume、布局与 MCP gateway；WorkspaceManager 负责 workspace_id 缓存、idle eviction 和 shutdown。源码真实存在，不能停留在早期 feature request 的判断。[Backend](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/workspace/_opensandbox/_opensandbox_backend.py)、[Workspace](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/workspace/_opensandbox/_opensandbox_workspace.py)、[Manager](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/app/workspace_manager/_opensandbox_workspace_manager.py)
- **主键是 workspace_id：** Manager 默认 isolation=PER_AGENT，支持 PER_SESSION/PER_USER；base 负责分配/持久绑定 workspace ID。OpenSandbox manager get_workspace 明确丢弃 session_id；同 workspace 内的 session 用 sessions/<session_id>/ 目录分区，不能理解为每 session 单独 sandbox。user/agent metadata 是运维筛选字段，不参与缓存 key；授权/租户约束不能只靠这个 cache。[Manager](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/app/workspace_manager/_opensandbox_workspace_manager.py#L199)、[ID 分配](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/app/workspace_manager/_base.py)
- **重连：** cache miss 时按 agentscope.workspace.id metadata 查 RUNNING/PAUSED，运行中 connect，暂停中 resume，否则 create；多匹配仅告警并选 created_at 最新的实例，未做遍历所有分页。单进程 lock 防止同 manager 并发重复 create，不能证明跨 worker 创建唯一或 metadata 即 exactly-once。[查找/连接](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/workspace/_opensandbox/_opensandbox_workspace.py#L216)、[Manager lock](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/app/workspace_manager/_opensandbox_workspace_manager.py#L234)

### 4.2 状态保留与清理

- **close 的含义：** Workspace.close 最终执行 sandbox.pause，再 sandbox.close 释放本地 transport；明确不 kill，目的是文件下次可重连。pause/close 错误 warning 后吞掉，handle 清空。因此“调用 close 返回”不是销毁成功证据。[teardown](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/workspace/_opensandbox/_opensandbox_workspace.py#L168)、[base close](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/workspace/_sandboxed_base.py#L216)
- Manager async with 启动 sweeper，默认 idle TTL=3600 秒、每 300 秒检查，evict 后 pause；退出时 cancel sweeper 并 close_all/gather，错误记录而不打断其他 workspace。idle TTL 与 OpenSandbox create timeout=300 秒是两件事；核查的 OpenSandbox workspace/manager 中未见 renew，不能保证空闲一小时之前实例始终存在，或暂停文件永久保留。[Manager](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/app/workspace_manager/_opensandbox_workspace_manager.py)、[constants](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/workspace/_opensandbox/_constants.py)
- initialize 在 provision 后建立布局、恢复 MCP、bootstrap gateway、迁移/seed skills，末尾才标 alive；其所查路径没有整体 try/finally 自动销毁新建沙箱。Manager 只有完整 initialize 成功后才缓存对象，因此中途 bootstrap 失败的回收不能由 close_all 必然覆盖。[base initialize](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/workspace/_sandboxed_base.py#L174)、[build_and_start](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/app/workspace_manager/_opensandbox_workspace_manager.py#L160)

### 4.3 工具、文件与测试的边界

- Backend 使用 async SDK；argv 经 shlex.quote 拼成 shell 字符串，传 cwd/command timeout；None exit code 和 transport error 映射为 -1，避免未知结果当成功。read_bytes / WriteEntry(bytes) 保留文件字节，父目录用 mkdir 命令建立。日志文本重组成 bytes，并非原始 subprocess 任意字节流；未见 stream byte budget 或任务结束强制清空。[Backend](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/workspace/_opensandbox/_opensandbox_backend.py)
- 文件状态主要留在 sandbox 内，管理器没有 host basedir/bind，不自动把本机仓库同步过去；技能/gateway script 等通过 Backend.write_file 上传。默认 Python slim image 以 root 在线 apt/curl/uv/pip bootstrap，gateway home=/root/.agentscope；其目的是可复用 agent workspace，不能直接复制到 YiPilot 的非 root、只读 rootfs、deny-all 任务策略。[Workspace bootstrap](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/workspace/_opensandbox/_opensandbox_workspace.py#L346)、[gateway 上传](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/workspace/_sandboxed_base.py#L440)、[constants](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/src/agentscope/workspace/_opensandbox/_constants.py)
- 实际 live tests 已覆盖命令/cwd/argv quoting/文件读写/目录 helpers，另有 initialize+MCP 测试；未设 OPENSANDBOX_DOMAIN 时 skip。固定 CI workflow 未配置该环境，也不部署 OpenSandbox，故普通 CI 成功不能证明这些 live case 跑过。另有不依赖服务的 None-exit-code regression test。live teardown 是 pause，不是资源完全删除；本次没有重跑测试。[backend tests](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/tests/backend_opensandbox_test.py)、[workspace tests](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/tests/workspace_opensandbox_test.py)、[CI](https://github.com/agentscope-ai/agentscope/blob/f2bedf3e5e3b7b3425d41d49b59af131fcd18cbe/.github/workflows/unittest.yml)

## 5. AgentScope Runtime：核查范围内未发现 OpenSandbox backend

固定 Runtime main commit `22072fd7075ce0c6f43cb39509d6a14b0e60ddb5` 的完整文件树没有 opensandbox 路径，pyproject 没有 opensandbox 依赖；内置 SandboxType 包含 BASE/BROWSER/FILESYSTEM/GUI/MOBILE/AGENTBAY 等，SandboxServiceFactory 仅注册 default。据此可以说“本次未找到 Runtime 主仓内置 OpenSandbox backend”，不能说整个生态不支持外部 adapter。应把上节 AgentScope 主仓 workspace 的正向事实与 Runtime 自有 Docker/远程 sandbox 分开。[Runtime tree](https://github.com/agentscope-ai/agentscope-runtime/tree/22072fd7075ce0c6f43cb39509d6a14b0e60ddb5)、[pyproject](https://github.com/agentscope-ai/agentscope-runtime/blob/22072fd7075ce0c6f43cb39509d6a14b0e60ddb5/pyproject.toml)、[SandboxType](https://github.com/agentscope-ai/agentscope-runtime/blob/22072fd7075ce0c6f43cb39509d6a14b0e60ddb5/src/agentscope_runtime/sandbox/enums.py)、[factory](https://github.com/agentscope-ai/agentscope-runtime/blob/22072fd7075ce0c6f43cb39509d6a14b0e60ddb5/src/agentscope_runtime/engine/services/sandbox/sandbox_service_factory.py)

## 6. 从第三方源码可提炼的模式

| 模式 | 已见实现 | 可借鉴部分 | 必须自行补齐的边界 |
|---|---|---|---|
| 应用创建，adapter 只做工具 | Ayush | 生命周期所有权清楚；稳定的执行/文件接口 | run/attempt 关联、超时取消、destroy 确认、输出审核 |
| backend 包办 create/kill | Hmzbo | 调用方便；持久 loop 避免跨 loop 客户端误用 | close transport、总 deadline、异常 orphan、版本固定 |
| workspace manager 持久复用 | AgentScope 主仓 | ID 绑定、metadata重连、cache/sweeper、pause/resume | 多 worker 唯一性、TTL续期、清理失败、敏感状态跨任务复用 |

上述项目展示了可行的工具接入与工作区编排，不自动证明 YiPilot 的严格执行证据、网络隔离、稳定结果导出与未知结果不重放要求已经满足；生产使用程度不能由 adapter 存在、README 或 CI 绿灯推出。
