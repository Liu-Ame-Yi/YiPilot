# 实施路线

状态：**目标路线，尚未完成。** 产品范围以 [产品定义](vision.md) 为准，实际进展以 [当前状态](status.md) 为准。

| 顺序 | 工作 | 退出条件 |
| --- | --- | --- |
| R0 统一入口与合同 | 收敛 CLI 编排；统一阶段输入、结果、错误与依赖装配 | 同一业务无需 stdin 也能调用，不新增第二条生产路径 |
| R1 持久化与恢复 | 按 V2 提案实施事务状态、工件、幂等、事件及旧数据迁移 | 重放、崩溃和外部结果不确定不会伪造成功或重复发布 |
| R2 通用 Agent 与工作区 | 多轮模型/工具循环、真实流、上下文、取消和受控执行 | 同一核心支持文档与代码任务，保护原工作区 |
| R3 本地研发闭环 | 文本/本地 PRD → SRS → 需求评审 → SDD → 设计评审 → 实现 → 验证/代码评审/修复 | 一次授权内自动推进；必要澄清可恢复，版本变化正确使旧结果失效 |
| R4 发布与交接 | 单个代码托管适配、分支/PR/MR、可选 CI/Jenkins、交接报告 | 结果绑定当前 SHA，重复请求和重启不重复发布；不执行合并 |

按职责迁移，保留已有 Docker、路径校验、Git 隔离、证据与模型配置能力；不先批量搬目录或创建空接口。SQLite、具体模块切分和首个 Git host 是技术提案，实施前按对应合同核验，不视为原项目既有事实。

先完成本地材料输入；PDF/Word、网页、Issue、企业文档和 MCP 只在明确使用需求后接入。缺陷描述走同一流程，不另外排独立 Bugfix Runtime。自动合并不属于“以后默认补上”的里程碑。

旧 M0–M8 规格与计划保留作历史证据，不与本表并行指导实施。详细验收见 [V2 里程碑](../superpowers/specs/2026-09-07-yipilot-v2-architecture.md#16-实施里程碑与验证)。
